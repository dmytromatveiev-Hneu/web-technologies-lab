## Контрольні питання

1. **Що таке Git?** Розподілена система контролю версій, що зберігає історію змін файлів.
2. **Що таке GitHub?** Онлайн-платформа для зберігання Git-репозиторіїв і спільної роботи.
3. **Що таке репозиторій?** Сховище файлів проєкту та історії їх змін.
4. **Для чого використовується GitHub?** Для розміщення проєктів, співпраці, обговорення й перевірки змін.
5. **Що таке commit?** Зафіксований стан проєкту з автором, часом і повідомленням.
6. **Що таке branch?** Окрема лінія розробки, у якій можна робити зміни незалежно від інших гілок.
7. **Для чого потрібна main?** За прийнятою домовленістю це основна гілка з актуальною версією проєкту.
8. **Що таке clone?** Створення локальної копії репозиторію разом з історією Git.
9. **Що робить git add?** Додає вибрані зміни до індексу для наступного коміту.
10. **Що робить git commit?** Створює локальний коміт зі змін, підготовлених в індексі.
11. **Для чого git push?** Передає локальні коміти та оновлення гілок у віддалений репозиторій.
12. **Для чого git pull?** Отримує зміни з віддаленого репозиторію та інтегрує їх у поточну гілку.
13. **Що таке Pull Request?** Пропозиція обговорити, перевірити та включити зміни з однієї гілки в іншу.
14. **Що таке Merge?** Об'єднання історії та змін гілок.
15. **Для чого README.md?** Для опису проєкту, структури й інструкцій користувачам.
16. **Чим Git відрізняється від GitHub?** Git керує версіями й може працювати локально; GitHub розміщує Git-репозиторії в Інтернеті та додає засоби співпраці.

## Додаткове завдання — Git на комп'ютері

На Mac уже встановлено Git: `git version 2.50.1 (Apple Git-155)`. Виконано клонування репозиторію, перевірку стану та отримання актуальних змін через `git pull --ff-only`.

Для локальних змін використано `git add` і `git commit`. Відправлення через `git push` ще потребує авторизації GitHub у командному рядку. Публікацію файлів через підключення GitHub у Codex не слід вважати виконанням команди `git push`.
